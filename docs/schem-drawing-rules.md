## A. 可机器校验（工程规则）

> 出处以 **KiCad 8 手册**为主（`docs.kicad.org/8.0/en/eeschema/eeschema.html`，文档
> GPL-3.0+ / CC-BY-3.0 ✓ 引用注明出处 ✓）。**能写成检查的就不靠人眼** ✓。

| # | 规则 | 出处（KiCad） | 我们的机器守 |
|---|---|---|---|
| A1 | **坐标落在网格上** —— 引脚/线端不落网格 ⇒ **看着连上其实没连** ✗ | KiCad："推荐 50 mil；用别的网格会导致**连通不正确**"；ERC `Symbol pin or wire end off connection grid` | ⚠ **这条在 Fritzing 里不适用** ✗（2026-09-26 实测）：Fritzing 存的是**连续坐标**、网格只是编辑辅助、**相位由画布决定** ⇒ 绝对坐标不必是整数倍 ✓；而且 Fritzing 的连接记在 `<connects>` 里 ⇒ **不会"看着连上其实没连"** ✓　⇒ `sch_style_check.py` 只把网格当**参考**打印（相位 + 偏离点）✓ |
| A2 | **连线只用 0 / 45 / 90°** | KiCad 三种线模式：90° / 45° / 自由角度（后者是特例 ✗）| 见 C 节（TODO）✓ |
| A3 | **交叉 ≠ 连接**（KiCad 靠线端 + junction，**Fritzing 靠 `<connects>`** ✓）| ERC `Label not connected` / `Wires not connected to anything` ✓ | **Fritzing 侧不需要这条检查** ✓ —— 连接是**显式**记的，不会出现 KiCad 那种假连接 ✓（所以 `sch_style_check.py` 不查它 ✓）|
| A4 | **一个网只能有一个名字** | ERC `More than one name given to this net`（warning）| `fzp_check.py` 第 ⑦ 条同精神（同名必同总线）✓ |
| A5 | **只差大小写的两个名字 = 疑似拼错** | ERC `Labels are similar (lower/upper case difference only)` | `sch_style_check.py` ③ ✓（`DATA_in` vs `DATA_IN` ✓）|
| A6 | **位号唯一 + 按位置排号 + 前缀按类型** | Annotate 按 X（左→右）/ Y（上→下）排序 ✓；`Duplicate reference designators` = **Error**；Symbol Checker：前缀**不许以数字或 `?` 结尾** | `sch_style_check.py` ② ✓（＋本仓既有的"**先左后右、先上后下**"✓）|
| A7 | **没用到的引脚要有交代** | 留空 ⇒ `Pin not connected`（Error）；故意不接要打 no-connect 标记 ✓ | 网表里写明"留测试点 / 悬空"✓（人守，本库已这么做 ✓）|
| A8 | **电源网必须有"驱动源"** | `PWR_FLAG`：不驱动 ⇒ ERC 报 "not driven by any Output Power pins" | 同精神：**EPAD 独立成网、必须特意接线** ✓（`fzp_check.py` ⑥ ✓）|
| A9 | **只用核心字体** | "自定义字体**不随工程走**，换机器会被替换" ⇒ 建议用 KiCad 自带字体 ✓ | 本仓：**只用 DroidSans** ✓（`AGENTS §5` ✓）|
| A10 | **值写法统一**（RKM）| 模拟器值记法：`4k7` / `100n` / `10R` ✓ | 文档规则：**不许** `4.7k` 与 `4700` 混写 ✗ |
| A11 | **元件符号自检** | Symbol Checker：引脚离网 / 重复引脚 / **零尺寸图形** / 位号前缀非法 ✓ | 本仓 `fzp_check.py` + `schem_check.py` ✓ |

### ★ 实测两条（2026-09-26，“检验规则可用性”实验的结果）

拿真实 sketch（`hardware/pixel/pixel.fzz`，14 个元件 / 32 根线）量的**硬数据** ——
这两条决定了 A1 “网格”在 Fritzing 里**只能当参考** ✗：

1. **引脚本来就不在网格上** ✗ —— 从线端反推出 **43 个 (元件, 引脚) 偏移**，
   其中 **25 个不是 100 mil 的整数倍**，涉及 6 个元件（`U1` / `C1` / `C2` / `J1` /
   `5V`、`G` 网络标签 / 面包板 ✓）⇒ **把元件锚点吸到网格，线端照样对不齐** ✓
   （Fritzing 的 core 符号自己就是这么画的 ✓）。
   对得上 KiCad 的另一半：它的符号库**必须**按网格设计 —— 因为 KiCad 靠**坐标重合**判连接 ✓。
2. **导线实例有“两套坐标”** ✗ —— 导线既是 `<instance>`（有自己的锚点 `<geometry x y/>` ✓），
   又有线端 `<geometry x1 y1 x2 y2/>` ✓，**两者不是一个数** ✓ ⇒ “全图对齐”得同时管两套 ✗。
3. 副产品：**规则本身是可用的** ✓ —— ① “线端 ↔ `<connect>` 顺序”经**自检**确认
   （两种顺序都试，零冲突的那个才对 ✓）；② 元件锚点吸附到 100 mil 后，网格相位分布
   从 `+0 × 72` 升到 `+0 × 88`（共 220 个坐标）✓ —— 提升有，但**到不了**全对齐（因为第 1 条 ✗）。

⇒ **结论**：“坐标必须落网格”在 Fritzing 里算 **B 节（编辑习惯）** ✓，别当 **A 节（可校验项）** ✗；
A 节真正能判 FAIL 的是“**位号 / 命名**”这类**语义**问题 ✓（`sch_style_check.py` ② ③ ✓）。

> `.fz` 结构细节（驼峰视图名 `schematicView`、`gridSize` 带单位、**导线也是 `<instance>`**✓）
> 记在 `tools/README.md` 的脚本行与 `tools/sch_style_check.py` 的文档串里 ✓。

### ★ B3.1 netlabel 的**用法**：只用在「功能独立出来的模块」的边界上 ✓（2026-09-29 用户定 ✓）

> 用户原话（这一条的意义就在这句里 ✓）：
> 「**把功能独立出来的模块，适合使用 netlabel，既方便功能检查、修改、调试，
> 也方便人的阅读和理解**」✓

- **用** ✓：**功能上独立成块**的模块，模块**与模块之间**的网 ⇒ 在**每个模块的边界**各放一个同名标签 ✓
  （**不把长线拉过别的模块** ✓）。好处就是那句原话 ✓：功能检查、修改、调试、阅读 ✓。
- **判据**（4 条 ✓，都从图上看得出 ✓）：
  1. 先能**指名**"这是哪个功能块" ✓（说不出功能块 ⇒ **不该用** ✗）；
  2. 标签贴在**模块边界**上 ✓ —— 模块**内部**照旧画实体线 ✓（标签不是"内部走线的替代品" ✗）；
  3. 一个跨模块的网 = **每个相关模块各一个**同名标签 ✓（**少而集中** ✓）；
  4. 贴了标签就必须**删掉**跨模块那段实体线 ✓（**总长/交叉必须降** ✓）——
     线要是还在 ✗ ⇒ 标签**没替掉任何东西** ⇒ 无意义 ✗。
- ✗ **禁止**：**把一根线从中间剪断、两个断口各贴一个同名标签** ✗ ——
  **净信息为零** ✗（那根线本来就在说"这两截是同一张网" ✓，剪断再接回去**没告诉读者任何新东西** ✗）。
  **反例（实测 ✓）**：2026-09-29 像素板 `pixel-schematic`：把 GND 上轨从中间切掉 **135.8 单位**、
  两个断口各贴一个 `GND` ⇒ 所有判据**全绿** ✓（网表 ✓ 9 网全对 ✓、假接头 0 ✓、悬空端不变 ✓），
  但用户判定「**毫无意义**」✗ —— **规则拦不住无意义** ✗，这一条就是为它写的 ✓。
- **机器守**（待补 ✗，记账在 C 节 ✓）：每个标签必须**替掉 ≥ 阈值长度**的连线 ✓；
  **同一点附近不得出现两个同名标签** ✗；**跨模块**的实体线不得残留 ✗。

#### B3.1.1 ★ **标签是一个元件** ✓（2026-09-29 用户补 ✓）

> 用户原话：「**标签是一个元件，跟元件一样，适用不能穿体等规则，要有引线连接。**」✓

1. **必须有引线连接** ✓ —— 标签脚与导线**端点重合**（真接上 ✓），
   ✗ **不许**“连接表里声明了、几何上线却停在标签脚前面” ✗（实测反例 ✓：用户手改稿
   `v31_rcgnd_byHand.fzz` 里 4 个标签全都差 **12～18 单位** ⇒ `(A) 假连线 = 4 处` ✗）。
2. **标签本体当障碍物** ✓ —— 和元件本体同待遇：
   · 导线**不许穿过**标签本体 ✗、**不许压在**它上面 ✗；
   · 标签本体**不许压**别的元件本体 / 别的标签 ✗；
   · 导线贴近标签脚也受同一个**安全距离**约束 ✓（本仓 `CLEAR_PIN = 7.2 单位 = 2.03 mm` ✓）。
3. **判据要与元件用同一份实现** ✓（别给标签另写一套 ✗）：
   项目侧 `render_sch.py` 已把标签本体登进 `PART_BOX` ✓ ⇒ “穿体 / 重叠 / 贴脚”三条自动管它 ✓。

#### B3.1.2 ★ **接地符号（GND）＝ “每块地各摆一个”** ✓（符号类元件与标签同待遇 ✓）（2026-09-30 用户定 ✓）

> 用户原话：「**主要思路是把 GND 标签换成了更常见的接地符号，这个符号，与 GND 标签起同样作用。**」✓

1. **用途与 netlabel 是同一件事** ✓ —— 都在说“**这块电路的地**”✓ ⇒ 作用在**功能模块**上：
   **每个模块各摆一个** ✓（与 B3.1 第 3 条同一条逻辑 ✓；本仓实例：`A = L1/D3/R1/C1` 与 `B = 以 U1 为核心` 各一个 ✓）。
2. ★★ **不要为了放符号去切网** ✗（反直觉 ✓，但这就是 Fritzing 的行为 ✓）：
   `LocalGrounds` 会把**全图**那些脚拉成**一张**网 ✓ —— 依据（源码 ✓）：
   · `connectors/connectoritem.cpp::isGrounded()`：`name ∈ {gnd, vss, ground}`（大小写不敏感 ✓）；
   · `items/symbolpaletteitem.cpp::busConnectorItems()`：`bus->id() == "groundbus"` ⇒ `mitems = LocalGrounds` ✓。
   ⇒ 两个符号**不必用线相连**也同网 ✓；**切开放标签/符号那套（B3.1 第 4 条）不要照搬到地上** ✗。
   **反例（实测 ✓）**：2026-09-30 像素板第一版把符号挂在“模块边界”的切口上 ⇒ 那个切口正好是
   一根长竖线的**顶端** ⇒ 符号的**图形被线穿** ✗（图上就是“符号挂在线上、线把三根横线打穿”✗）。
   ★ 反过来：**图里没有接地符号 ⇒ 什么也不合并** ✗ —— 那些脚只是“名字叫 GND”而已 ✓。
3. **符号是元件** ✓（与 B3.1.1 同一条 ✓）：**必须有引线接上** ✓（脚与线端重合 ✓）；
   本体当障碍物 ✓（导线**不许穿过**它的图形 ✗、**不许压**别的元件本体 / 元件文字 / 别的标签 ✗）。
4. **形状决定挂法：往下挂** ✓ —— 脚在图形**上缘** ✓、图形**向下**展开 ✓（本仓 `sch_net.GROUND_ART_BOX` ✓）
   ⇒ 只挂在**能从上方/水平走线过来**的点上 ✓，而且**挂点要挑** ✓：
   候选 = 该网**已有的结点/端点** ✓（脚上不挂 ✗）；判据 = **违例 0** ✓（引线压线 / 交叉 ✗、
   引线蹭脚 ✗、图形**被线穿** ✗、压本体 / 元件文字 / 别的符号 ✗）；并列时取**离本模块的脚最近**的 ✓。
5. **机器守** ✓：立项实现见 `hardware/pixel/check_grounds.py` ✓（`py -3.13 check_grounds.py <sketch.fzz>` ✓）——
   查三件：**脚上必须真有线端点** ✓、**没有线穿过那块图形** ✗、**盒里没有引脚** ✗；
   **退出码非 0 = 不合格** ✓。★ 它**只豁免脚周围 1 单位**那一小截 ✓ ——
   ✗ 若把“终止在脚上的那根线”**整根豁免** ⇒ “线从符号身上穿过去”的错版**照样通过** ✗
     （= 自证 ✓，实测踩到过 ✓）；★ 图里没有接地符号 ⇒ **拒判**并退 2 ✗（不许“空集当通过” ✗，
     与 `check_flags.py` 同一条 ✓）。
