## 0. 一条总纲：面包板要的是**物理连接**，不是"同名即通" ✗

- **netlabel / 网名 = 抽象连接** ✗ ⇒ 只适用于**原理图** ✓；
  面包板上没有抽象 —— 两根线之间**必须有导体**（导线 ✓ 或**同一条 bus 的铜片** ✓）。
- 三条推论（写生成器 / 写自检都必须遵守 ✓）：
  1. 不许把"元件脚属于同一个网"当成"已经连上了" ✗ —— 同网只是**待办清单** ✓；
  2. **一条 bus 上挂了两个不同网的脚 = 实物短接** ✗（一列 5 孔是同一块铜 ✓）⇒ 必须挪脚 ✗，
     不许当成"两网已合并"去补线 ✗；
  3. 自检顺序：**先**查"没有 bus 跨两个网" ✓、**再**查连通 ✓（反了会报假通过 ✗）。

## A. 可机器校验的规则（工程规则 ✓）

> 原则：**能写成检查的就不靠人眼** ✓；每条都要说得出**谁在守它** ✓。
> 现状（`pixel-breadboard104.fzz` ✓，2026-09-27）：**10 条全 0 违规** ✓。

| # | 规则 | 为什么（物理/电学）| 我们的机器守 |
|---|---|---|---|
| A1 | **一个孔最多一个"端点"** —— 元件脚 **或** 导线端点，二者只其一 | 孔径/线径决定，插不下第二个 ✗ | 项目自检 ①「一孔一端点」✓ |
| A2 | **引线不许盖住"接了线的孔"**（开口面积 > **30%** 即算 ✗）| 盖住就插不进线了 ✗ | 自检 ②「遮挡接线孔」✓ + 生成器 `obscures()`（**一份实现** ✓）|
| A3 | **引线之间不许重叠**（共线叠在一起 ✗）| 两根线压在同一位置 ⇒ 看错/拨错 ✗ | 自检 ③「引线重叠」✓ + 生成器 `route_cost` ③ ✓ |
| A4 | **不许从别人的元件本体框下面穿过** ✗ | 实物挡着，根本走不了 ✗ | 自检 ④「孔在本体下」✓ + `route_cost` ② ✓ |
| A5 | **一条 bus 不许跨两个网** ✗（实物短接）| 一列 5 孔是同一块铜 ✓ | 自检 ⑤「bus 短接」✓ + **生成器开场的硬闸门**（命中就报错、**不写文件** ✗）|
| A6 | **每个网必须物理连通** ✓ | 见 §0 ✓ | 自检 ⑥「网连通」✓ + 项目网表核对（`check_netlist.py` ✓）|
| A7 | **导线颜色只能用 Fritzing 官方色表** ✗ | 表外的 hex **画得对、但指示栏认不出** ✗ ⇒ 回退成"蓝" ✓（实测 ✓）。★ **同一个颜色名字在不同视图值不同** ✗（面包板橙 `#ef6100` ✓ / **原理图**橙 `#ff7300` ✓）⇒ **必须按视图取那一节** ✓ —— ✗ 一张表管两个视图**必然错一边** ✗（2026-10-16 实测 ✓）| **唯一一处表** = `tools/fz_colors.py` ✓（它自己拿 Fritzing 的 `ratsnestcolors.xml` 逐色自校 ✓）；**闸门** = `tools/file_sanity.py` ✓：**① 面包板** ✗ ＋ **①b 原理图** ✓（2026-10-16 补 ✓，用户定「必须补」✓）＋ **①c 白/黄只提醒** ✓；退出码 **1** ✓（★ 如实：这个退出码也是 **2026-10-16 才补的** ✗ —— 之前它**没调 `sys.exit`** ✗ = 不会红的闸门 ✗）|
| A8 | 不许**零长线段** ✗ / 非法属性 ✗ | Fritzing 里会多出可见节点 ✓ | `file_sanity.py` ② ③ ✓ |
| A9 | **脚位必须真的落在孔上** ✓ | 差一点就插不进 ✓ | 项目脚位自检（**按 sketch 的 `<leg>`** = Fritzing 自己的口径 ✓；只读 svg 会**误报** ✗）|
| A10 | **斜线不超预算**（见 B5 ✓）| 人看着漂不漂亮 ✓ | `tools/bb_diag_list.py`（**逐条点名** ✓）+ `bb_compare.py`（计数 ✓）|
| **A11** | ★ **就近选孔**：一条跳线的**锚孔**必须取「**可用孔集合**」里使这条跳线**最短**的那颗 ✓（判据 = **拐点少 → 总长短** ✓；平手比「离其它已占孔远 → 孔编号小」✓）。**可用孔** = 空的 ✓ **且**所在 bus **不跨别的网** ✗ **且**换完**逐网仍连通** ✓ | **物理/电学**：孔离脚越远 ⇒ 线越长 ⇒ 越挤越绕 ✓；而"同一 bus 内换孔"电气完全等价 ✓（B8 ✓）⇒ 纯赚 ✓ | `bb_route4.py` 的 `pass_near_hole()` ✓（`--near-hole` ✓ **缺省关** ✗）；探针 `hardware/pixel/tools/bb_probe.py` ⑧ ✓ |
| **A12** | ★ **能直就直**：两端**同行或同列** ⇒ **一根直线段**（0 拐点 ✓）；否则**拐点最少优先**、**其次总长最短** ✓；只有"必须避让"（重叠 ✗／穿本体 ✗／盖接线孔 ✗）才允许多拐点 ✓。★ **不比交叉** ✗ —— 面包板上**交叉是允许的** ✓ | 用户 2026-10-09 定 ✓（原话：「面包板视图里跳线交叉是允许的 —— 不比交叉，只比拐点/长度/避让」✓）；线越直越看得懂 ✓ | `bb_route4.py` 的 `pass_straight()` ✓（`--straight` ✓ **缺省关** ✗）|

| **A13** | ★ **脚不许"缩进本体"**：同件内**脚与脚的间距**必须等于**元件自称的间距** ✓（残差 = 每只脚 `geometry − 自称脚位` **减掉平均值**后的余量 ✓；容差 **2.0 mm** ✓）| Fritzing 画的"脚"就在那个位置 ✓ ⇒ 脚位被改写（拖过／被别的程序写过 ✗）⇒ **引线缩进本体** ✓、拖出一条**横跨两颗孔的长橡皮筋** ✗、★ **在 Fritzing 里那只脚的"可点位置"不在你看到的地方** ✗ | `tools/bb_precheck.py` **⑥** ✓（实测：用户亲手画的 9 张台架图最大 **0.22 mm** ✓ 零误报；用户认可"不用改"的 `R1` **0.50 mm** ✓；用户报"位置错误"的 `R3` **3.19 mm** ✗）|

### ★ 实测三条（都是"数字骗过人"的教训 ✗）

1. **判碰只有一份实现** ✓ —— 度量工具与优化器**共用** `bb_compare.pair_kind` ✓；
   抄一份就多一个错处 ✗（实测：两套口径让数字对不上、找不到原因 ✗）。
2. **几何公式必须拿手算真值对一遍** ✓ —— "圆弓面积比"曾被写反平方根项 ✗ ⇒
   只算真值的 ~1/5 ✗（穿心真值 78% vs 报 15% ✗）⇒ A2 那条硬规则**形同虚设** ✗。
3. **判"盖住"要带容差** ✓ —— 板框走过 `transform` 带浮点误差 ✗ ⇒
   精确比边界会把**压在板边上**的孔判成"没盖住" ✗（实测 `108.00009` vs `108.0` ✗）
   ⇒ 全仓统一 **±1 单位**，且生成器与校验器**同一个口径** ✓。
4. **同一个名字在不同视图值不同 ⇒ 表必须带"视图"这一维** ✗（2026-10-16 ✓）——
   官方表里橙在**面包板**是 `#ef6100` ✓、在**原理图**是 `#ff7300` ✓；项目数据当时只有
   **一张** `COLOR` ✗ ⇒ 为修原理图（用户报"那根橙线看不见"✗）把表改成原理图值 ✗
   ⇒ **面包板全错** ✗（`file_sanity` ① 报 3~5 根 ✗；症状 = **颜色下拉回退成"蓝"** ✓）。
   ⇒ 现在：`COLOR` = 面包板 ✓、`COLOR_SCH` = 原理图覆盖 ✓（`sch_route.py` 认它 ✓）；
   **闸门补上了** ✓（`file_sanity.py` ①b ✓，2026-10-16 用户定「必须补」✓）。
   ★ 一般化：**只要某参数在两类对象上取值不同，就别用同一张表** ✗；
   而这类表还应当**只有一处定义** ✓（表抄成 4 份 ⇒ 改一处忘三处 ✗，本次就是这么栽的 ✗）。

> 各条的项目级实现在：`hardware/pixel/audit_layout.py`（①②③④⑤⑥ ✓）、
> `tools/file_sanity.py`（⑦⑧ ✓）、`hardware/pixel/render_bb.py`（⑨ ✓）、

## B. 口径与审美（人定 ✓，每条都带原话或可算的推导 ✓）

> 一句话：**布线器的目标 = 长度 + K × 交集** ✓，其余的"美感"都写成这条式子里可算的项 ✓；
> **说不出理由的偏好一律不加** ✗（`AGENTS §1` 工业风）。

| # | 规则 | 出处 / 推导 | 落在哪一行 |
|---|---|---|---|
| B1 | **布线次序**（最高优先级）：元件布置 → **从左到右、从上到下**布电源/地 → 再布其它线 | 用户 2026-09-26 定 ✓（"从大到小、从主到次" ✓）| 生成器的分组：GND/5V = 组 0/1 ✓、信号 = 组 2 ✓ |
| B2 | **目标函数 = 长度 + K × 交集**，**K = 10 mm / 交集**（**人为可调** ✓，"为了少 1 个交叉最多值得多绕 K 毫米" ✓）| 用户 2026-09-26 定 ✓ | `K_MM = 10.0`（一行 ✓）|
| B3 | **「交集」= X 形交叉 + T 形搭线 + 从元件底下穿过**，三类**各算 1 次** ✓；接同一个孔 / 同一根的串接段**不算** ✗ | 用户 2026-09-26 当天修正 ✓（我先后只数 X ✗ ⇒ 目标函数 ≠ 用户看到的东西 ✗）| `pair_kind`（**唯一实现** ✓）|
| B4 | **留路**：先布的电源/地尽量**走电源轨与板边**，把**中间走廊留给信号线** ✓；信号线不受此限 ✓ | 用户 2026-09-26 定 ✓（实测：先布的 GND 把 BR+ 唯一的走廊吃掉 ✗ ⇒ 后面无路可走 ✗）| `route_cost` 里的 `MID_PEN`（**只在贪婪阶段**加 ✓）|
| B4b | ★ **但"留路"不该在收尾再罚** ✗ —— 收尾时已经没有"后面的线"要留路了 ✓ | 实测 ✓：用户那一手被假拒（`583.2→585.8` ✗ = −5.1 长度 + 3.0×2.54 留路罚 ✓）| `layout_score(use_mid=…)`，收尾传 `False` ✓ |
| B5 | **斜线预算：不是越少越好** ✗ —— 0 条"不自然" ✗、9 条"不漂亮" ✗；目标 **≤4 条、且尽量和用户手画的一样** ✓ | 用户 2026-09-27 定 ✓（"1.25 的几根斜线，深得我心" ✓）| `DIAG_PEN = 1.25` ✓（一行）|
| B5b | **斜线罚要按"逐段"算** ✓ —— 禁止"点数 > 2 就免罚"的老口径 ✗ | 推导 ✓：老口径让"斜线 + 一小段直"**绕过**罚 ✗ ⇒ 实测斜线 1 → 9 条 ✗ | `shape_factor`（与 `_shape_total` **同一把尺子** ✓）|
| B5c | **1.25 是算出来的** ✓：手版那根 5V 斜着走 = `13.7P + 27.9`、正交走 = `45.7` ⇒ 斜线胜出要 **P < 1.30** ✓ | 实测扫描 ✓（1.15⇒6 条 / 1.25⇒4 条 ✓ / 1.30·1.35⇒4 条但 `LED_DIN` 变斜 ✗ / 1.50⇒0 条 ✗）| 同上 |
| B6 | **颜色 = 网络语义** ✓（黑 GND / 红 5V / 其余各网一色 ✓）+ **画完附"颜色 ↔ 网络"图例** ✓ | 用户 2026-09-26 定 ✓ | 项目图例生成器 ✓ |
| B7 | **元件摆位**：两排针元件**必须骑中缝**（一排上一排下，y 无自由度 ✗）；单排针可上/下半区 ✓ | 用户 2026-09-26 定 ✓ | 项目布置器 ✓ |
| B8 | **换孔 vs 换接**：同一 bus 内换孔 = **电气等价** ✓（随便换 ✓）；**换 bus = 拓扑变更** ✗（另一回事，见 B9 ✓）| 推导 ✓ | `pass_clear_way`（换孔 ✓）/ `pass_retie`（换接 ✓）|
| B9 | **一条 tie 只许"只动这一根"** ✓ —— 其余线**一根不碰**，且**网必须仍连通** ✓ | 用户手版 2026-09-27 ✓（全图只改一处 ✓）| `pass_retie` ✓ |

### ★ 两条"不许自证"的纪律（都是血泪 ✓）

1. **不许用同一份实现自证** ✗ —— 优化器与它的自检共用几何定义 ⇒ 它错时两边一起错、
   自检永远通过 ✗。结论必须能被**另一个实现**或**人的眼睛**推翻 ✓（数量用独立工具复核 ✓、
   与用户手版的图对量 ✓、最终**以渲染图/用户截图为准** ✓）。
2. **比对的两边必须同一组参数** ✓ —— 曾因"旧路由漏传自己的元件豁免 ✗、候选传了 ✓"
   ⇒ 每轮都报"有改进"✗ ⇒ 同一根线反复重排、全局一动不动 ✗（连着 8 轮 ✓）。

## C. 算法骨架（每一遍在修什么 ✓）

顺序就是本仓像素板的实际顺序 ✓；**每一遍都必须说得出"它比上一遍多解决什么"** ✗ 说不出的就不该加 ✓。

| # | 这一遍 | 能改什么 | 判据 | 实测收益 |
|---|---|---|---|---|
| C1 | **贪婪**（分组 + 留路）| 从零把每根线放下去 | 硬约束过滤 + 键 = 交集 → 折弯 → 形状加权长 ✓ | 走廊不被吃掉 ✓（`BR+` 才连得上 ✓）|
| C2 | **抽出重排**（8 轮，交替方向）| 把**一根**抽出来、在"看得见其它所有线"的条件下重放 | 两段式：先按交集、再按 `长度 + K×交集` 算账 ✓ | 交集 4 → 1 ✓ |
| C3 | **成对重排**（2-opt）| **同时**动两根 | 同上（同一把尺子 ✓）| 常见"两根互相绊住" ✓ |
| C4 | **换孔让路**（`pass_clear_way`）| 为**别人**让路：把挡路那根挪到**同 bus 空闲孔** ✓ | 硬规则全空 + **形状加权代价**变小 ✓ | 让"想走的更好走法"落地 ✓ |
| C5 | **破局重排**（R&R）| 把所有**还有交集**的线一起抽掉、按两种顺序整批重放 ✓ | 同上 | 一次跨过局部最优 ✓ |
| C6 | **单条 tie 换接**（`pass_retie`）★ | **换"接到哪条 bus"**（拓扑 ✗）—— 只动这一条 ✓；多余的 tie 直接删 ✓ | 硬规则全空 + **网仍连通**（**从零算** ✗：全局 `find()` 只增不减、删线后会说谎 ✗）+ 代价严格变小 ✓ | 例：GND 少绕 5.1mm ✓ \+ 5V 少绕 10.2mm ✓（**超越用户手版 10.1mm** ✓）|

> ★ 收尾的**统一验收**：`hard_bad()` 全空 ✓ + 代价**严格**变小 ✓；收尾那几步用
> `layout_score(use_mid=False)` ✓（B4b ✓）。
> ★ 诊断开关（出问题先打开它 ✓，本仓实测两个 bug 是"静默失败" ✗，不开看不见 ✗）：
> `PP_CW_DEBUG=1` ✓；另有 `PP_DIAG_PEN` / `PP_SHAPE_ACCOUNT` ✓。

### A.4 ★★ 摆位先于入网（2026-10-15 用户定 ✓）

用户原话 ✓：「**给面包板加一条规则吧：入网的前提是摆位到位，而不是随意都可以入网**」✓

**病（实测 ✓，`pixel` 板 v0.1.2 上撞的 ✗）**：新加的几个件被"克隆实例块"放在**同一列** ✗
⇒ 布线器照样按"就近选孔"把它们**接进了各张网** ✗ ⇒ 事后用 `bb_probe` 能查出**同一个孔**
（`pin16F`）同时出现在 `DATA_IN` / `DATA_IN_C` / `DATA_OUT` / `RC` **四张网**上 ✗✗
（= 一根 bus 挂四张网 = **真短路** ✗ —— 它报在**短接**那一条 ✓）。
★ **病根不是布线器算错** ✗ —— 是它**不会因为"摆位没到位"而拒绝布线** ✗。

**规则**（**前置**闸门 ✓，✗ 不是事后检查 ✗）：一件要参与布线，先要**摆位到位** ✓ ——

1. **每个脚都落在面包板孔上** ✓（✗ 悬空 / 压在两排孔之间 ⇒ 没到位 ✗）；
2. **同一件的脚落在不同的 bus** ✓（两只脚同 bus = 自己短自己 ✗）；
3. **不压别的件本体、不重叠** ✓（见上面 ⑤/⑥ ✓）；
4. 不满足 ⇒ **布线器直接报错退出** ✗、**不写文件** ✓
   （✗ 不许"随便给个孔就把脚接上" ✗）。

**机器守 ✓**：**事前** = `bb_precheck` ✓（①每个脚声明真孔 / ②接点落孔 / ④孔占用唯一 / ⑤一 bus 一网 / ⑥脚距 = 元件自称 ✓）；
**事后** = `bb_probe` ✓（①每网连通 / ②短接 / ③表图相符 ✓，只看 `<connect>` ＋ `<buses>` ✓）。
两者**同一套口径** ✓（都按"脚—孔—bus"的声明关系判 ✓），✗ 不另写一份 ✗。

★★ **孔位必须按"板子实际摆放"算** ✓（2026-10-16 根治 ✓）—— ✗ 不许把板位写死 ✗：
`bbb_compare.ROW_Y` / `9.0 × 列` 这一套隐含了"**板子落在 `CANON_BOARD = (-4.6484, 0)`**" ✓；
用户把**板子本体**平移一格（为了让某件靠最左 ✓）之后，写死的孔位就**整片错位** ✗
⇒ `bb_precheck` ② 当场报 **55 条"腿端差 3.59mm"** ✗ —— 而 **3.59mm 恰好 = √(8.98²+9.00²) 单位
= 板子挪的那一格** ✓（实测 ✓，一分不差 ✓）⇒ **那是尺子的问题，不是图的问题** ✗✗。
⇒ 口径改成：**孔位 = 基准 ＋ (`board_off_root(root)`) 的偏移** ✓
（`bb_compare.board_off_root` / `board_off` 是**唯一实现** ✓；缺省 `(0,0)` = 老行为一字不改 ✓）；
已接上的：`bb_compare.metrics` ✓、`bb_precheck.holes_of` ✓、`render_bb` ✓、`diag_pair` ✓、`bb_route4` ✓
（后者原来**自己又抄了一份** `ROW_Y`/`COL_PITCH`/`hole_xy` ✗ ⇒ 一并改成**委托** `bb_compare` ✓）。
★ 只处理**纯平移** ✗：板子带非平移的 `<transform>`（旋转/缩放 ✗）时**报一声、退回 (0,0)** ✓（不静默 ✓）。

**同源教训 ✓**：本次是生成器"**只抄了写法、没重给坐标**" ✗（克隆实例块 ⇒ 位置全一样 ✗）
⇒ 位置与接法脱节 ⇒ 短路 ✗。⇒ **位置必须有唯一来源** ✓，✗ 不许"默认继承上一个件" ✗。

### A.5 ★★ 物理在前，声明在后（2026-10-15 用户定 ✓）

用户原话 ✓：「**物理上管脚没有插入孔，也没有导线，怎么会接上了呢？你只会用数字连通吗？
能把物理模型放在第一位吗？**」✓

**病（实测 ✓）**：我给新件写了 `<connect connectorId="pin47J" …>` ✗，但**画的坐标并没落到那个孔上**
✗ ⇒ Fritzing 照这行声明把脚画成**绿色（已连）** ✓ —— 而它**物理上悬在空处** ✗。
对照 ✓：用户**随手摆上**的一只二极管画成**红色（未连）** ✓ —— 因为 **Fritzing 的红/绿是它自己按物理算的** ✓。

**规则 ✓**：

1. 面包板里**连通的第一性原理 = 脚（盘心）落在孔（孔心）上** ✓ —— 落了孔，Fritzing **自己**就认 ✓
   （孔＝同一条 bus ⇒ 天然同网 ✓）；
2. `<connect>` 是 Fritzing **记下的结果** ✓，✗ **不是**用来"建立连接"的手段 ✗
   ⇒ **先有几何（落孔）、后有声明** ✓，✗ 顺序不许倒 ✗；
3. 凡「**声明说连上、几何上没落孔**」⇒ **一律算错** ✓（"数字连通"不算数 ✗）；
4. 闸门判据 = **几何**（脚心 ↔ 孔心 距离 ≤ 容差 ✓），✗ 不是"有没有 `<connect>`" ✗；
   并且**与 Fritzing 同源** ✓（§13「只允许一个声音」✓）；
5. **导线**由布线器写声明 ✓ 是合法的 ✓（导线本来就是声明式的 ✓）——
   区别：**件**靠**落孔** ✓、**导线**靠**端点声明** ✓，两码事 ✗ 不许混 ✗。

**与 A.4 的关系 ✓**：A.4 说「别乱摆就接线」（**前置**✓）；A.5 说「**"连"这个动作本身必须是物理的**」✓
—— 两条合起来 ＝ **摆位到位 ⇒ 天然连通 ⇒ 才谈布线** ✓。

## E. v0.3.0 新增（2026-10-15 ✓，像素板 v0.1.2 面包板重做时实测 ✓）

本轮"板子放不下"的结论**全被推翻** ✗ —— 真因是 **6 个工具自己的缺陷** ✓（详见项目
`hardware/pixel/README.md` 五十九 ✓）。下面 4 条已够格写成**规则** ✓（另 2 条是纯 bug 修复 ✗）：

### E1 ★★ 橡皮筋腿件的"孔"以**它自己声明的**为准 ✗（不许用"离盘心最近的孔" ✗）

- 病 ✓：`C2`/`R1` 这类 `.fzp` 写了 `legId` 的件，腿是**被拉长**到孔上的 ✓ ⇒
  它们声明的孔**不是**几何上最近的孔 ✗（v87 实例：`C2.connector1` 真孔 = `pin28Z`（GND 轨）✓，
  而"最近孔" = `pin28Y`（5V 轨）✗）。
- 后果 ✓：把工具"按最近孔重算"一用 ⇒ `C2` 变成"GND 挂在 5V 轨上"= **假短路** ✗ ⇒
  那个 5V 轨（50 孔一条 bus ✓）被污染 ⇒ **新件 `D4` 的 830 个候选里 420 个被误杀** ✗。
- 规则 ✓：**逐脚记 `delta = 真实孔位 − 自然位置`** ✓、摆放时整体跟着平移 ✓；
  声明明显是**复制来的**（`|delta| > 1.5 格`）⇒ 当"新件"、`delta` 记 0 ✓。
- 机器守 ✓：对账——**老件逐脚**「文件声明的孔 ↔ 工具算的最近孔」必须**全部一致** ✓
  （实测 13/13 ✓；新件本来就该不一致 ✓）。

### E2 ★★ 「就近选孔」必须跑在**最后** ✓（判据要对**定稿的线集** ✓）

- 病 ✓：原来次序是 `①就近选孔 → ②能直就直` ✗ ⇒ ① 拿的是**扫描那一刻**的线集 ✓，
  而后面还有重排/换接会把线挪走 ✗ ⇒ 有的孔"当时被压住 ✗、定稿时其实干净 ✓" ⇒ ① **白拒** ✗。
- 实测（交付件本体量的 ✓）：`pin17H` 最终遮挡 **0.1%** ✓、不在本体下 ✓、属 GND bus ✓ ⇒ 完全可用 ✓；
  而 `pin17G`/`pin15F`/`pin16E` 是 **78.3%** ✗（真被压住 ✓）。① 却因为**当时的**状态把 `pin17H` 也拒了 ✗
  ⇒ EPAD 线退到 20.1 mm 外的 `pin24G` ✗（最近只要 10.2 mm ✓，探针 ⑧ 一直报 ✓）。
- 规则 ✓：**① 放在 ② 之后** ✓（① 的取舍用 `(拐点数, 总长)` ✓ ⇒ 不会把刚捋直的线掰弯 ✓）。
- 另一条同类病 ✓：**额外线（EPAD）就近选孔时没把自己摘出场** ✗ ⇒ 自己的旧走法挡住自己的新孔 ✗
  （跳线那边早有 `SKIP[0]=i` 这招 ✓）⇒ 先 `del extra[ix]` + 刷新 `fixed_segs` ✓、扫完原样插回 ✓
  （★ 回插用 `insert(ix, …)` ✗ 不是 `trial[ix] = …` ✗ —— 后者在最后一条上直接 `IndexError` ✓）。
- 机器守 ✓：探针 ⑧「**锚孔是不是最近可用孔**」✓ —— 且它的"可用孔"必须含
  **①扣掉被本体压住的孔** ✓ ②**规则⑤**（要占的孔已被别线盖住 ✗）✓ 两条缺一都会**假警报** ✓。

### E3 ★ 板侧回指表用 `layer="breadboard"` ✓（零件侧才用 `breadboardbreadboard` ✓）

- 口径出处 ✓ = **用户自己在 Fritzing 里存过的 `pixel-pcb-v87.fzz`** ✓：
  板侧 `<connect connectorId=<零件脚名> modelIndex=<零件> layer="breadboard"/>` ✓、
  零件侧 `<connect connectorId=<孔名> modelIndex=<板> layer="breadboardbreadboard"/>` ✓。
- 病 ✓：板侧也写 `breadboardbreadboard` ✗ ⇒ 读文件的一侧会把板侧那条当成"零件插孔" ✗
  ⇒ 造出 `plugged['connector0']` 这种**假孔名** ✗ ⇒ 下游 `KeyError` ✓。
- 机器守 ✓：**读 `plugged` 必须跳过面包板实例** ✓（`bb_compare.load` 已修 ✓）。

### E4 ★★ `--nets=` 这类"换输入"的参数，必须有一条**"改输入 ⇒ 结果必须变"**的冒烟测 ✗

- 病 ✓（最贵的一条 ✓）：`bb_route4.py` 把 `--nets=` 摘出来存了 ✓、却**没传下去** ✗
  ⇒ 一直读项目缺省那份**旧网表** ✗ ⇒ ① 新件一根线都不接 ✗ ② 它布出来的线与上一版**逐根相同** ✗
  ③ **连"判据"一起被骗** ✗（摆位器的判据＝真跑这条命令 ✓ ⇒ 报"0 张不通" ✓ 而新件根本没参与 ✓）。
- 规则 ✓：凡是"换输入"的开关，验收时要**故意换一份输入**、看输出**是否真的跟着变** ✓；
  ✗ 不许用"命令跑通了"当"参数生效了" ✗（本仓 `AGENTS §13` 的"不许自证"同源 ✓）。
- 机器守（待补 ✗）：给 `bb_route4` 加一条冒烟测——用两份**只有一处不同**的网表跑同一份 sketch ⇒
  结果必须不同 ✓。
