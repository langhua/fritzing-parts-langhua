## ★ 三个视图（2026-10-07 加：面包板 / 原理图 ✓）

`diff_revs.py` 现在能比 **三个视图** ✓：`--view pcb（默认）| bb | sch`。

| 视图 | 文件名的模式（设置项 ✓） | 清单里的 ② 那一节 |
|---|---|---|
| **PCB** | `pixelDiff.fzzPattern`（默认 `\.fzz$`） | 网络 / 铜块 / 过孔（原有 ✓）|
| **面包板** | `pixelDiff.bbPattern` | **跳线变化**：新增 / 没了 / 变了（**按"接的哪两个孔"认一条跳线** ✓ ＋ 端点 Δ mm ＋ 长度 Δ mm ✓）|
| **原理图** | `pixelDiff.schPattern` | **导线指标对比**：导线数 / 元件数 / 总长 / 交叉 / 正交度 / 最歪 ✓ |

★★ **面包板的跳线按"孔"认，不按"名字"认** ✓（2026-10-08 ✓）—— 这是被"看着很乱"逼出来的 ✓：
Fritzing **一存就把所有 Wire 重新编号** ✓（实测 `pixel-breadboard95 ⇒ 104`：19 条连接里
**14 条一模一样** ✓，而**一个旧名字都没留** ✗）⇒ 按名字比时它们变成「28 条新增 ＋ 28 条没了」✗
⇒ 图上凭空冒出 28 对红圈红字 ✓（用户：「面包板比较是这样的，看着很乱啊」✓）。
⇒ 身份 = `bb_compare.Link.ident` = **接的哪两个孔**（`pin<列><行>` ✓ 跨版本稳定 ✓）；
   **图例色条**（两头都没接 ✓）**不算跳线** ✗（实测 v95：28 条 Wire 里 9 条是色条 ✗）；
   且**图与清单共用 `_link_same()` 一份判据** ✓（原来各判各的 ✗ ⇒ 图上标 17 处「线路变了」、
   清单里写「没动 17 条」✗）。改完：v95 ⇒ v104 是 **5 新增 ＋ 5 没了 ＋ 4 变了 ＋ 10 没动** ✓。

① 元件摆位 Δ mm 那一节**三个视图共用** ✓。

**颜色口径不同 ✗**（不是为了好看，是因为它们没有“层” ✗）：
PCB 是「色相 = 层（顶橙 / 底蓝）、深浅 = 版」✓；
面包板 / 原理图是「**色相 = 类别**（导线橙 / 元件蓝 / 文字灰）、**深浅 = 版**」✓，
底不铺色（铺了会把另一版盖住 ✗）。

**对齐也不同** ✓：PCB 靠**板框** ✓；bb/sch 靠**并集窗口** ✓ —— 因为两个渲染器都把内容画在
**绝对 sketch 坐标**上 ✓（只是各自把窗口裁到内容 ✓）⇒ 不缩放不平移，谁挪了就是挪了 ✓。

**产物名**：`diff-<视图>-<A>-<B>.{svg,png,md}` ✓（没视图段的旧文件 = PCB ✓）
⇒ 幻灯片/编辑器**都认** ✓，页序按「视图（PCB ⇒ 面包板 ⇒ 原理图）⇒ 版本号」✓。

**复用（没有重写几何）** ✓：bb/sch 的渲染走 `render_bb.py` / `render_sch.py`
（它们是脚本式 ✗ ⇒ 子进程调 ✓，它们本来就顺手写 `.svg` ✓）；跳线变化读 `bb_compare.load()` ✓、
导线指标读 `sch_metrics.metrics()` ✓ —— 每个口径**只有一份实现** ✓。

## ★ 用到别的电路设计里（移植 ✓ · 2026-10-07 加）

**装一次就是全局的** ✓（拷进 `%USERPROFILE%\.vscode\extensions\` ✓）⇒ **任何窗口、任何项目**里
三个命令都在 ✓、**双击** `diff\diff-*.md` 也进合并视图 ✓（自定义编辑器匹配的是
`**/diff/diff-*.md` ✓，与项目名无关 ✓）。**新项目不用重装** ✓ —— 只有改了扩展本体才要
重跑 `tools\install_diff_ext.cmd` ＋ `Reload Window` ✓。

### 三条路各自要什么

| 入口 | 要什么 |
|---|---|
| **双击** `diff\diff-*.md` | **零配置** ✓：那份 md ＋ 旁边同名 svg 就够 ✓（不读任何设置 ✓）|
| **幻灯片** | 能认出**项目目录** ✓（见下 ✓）|
| **比较两版 / 比较两个文件** | 项目目录 ＋ **本库**（`tools/diff_revs.py` 所在的仓要加进工作区 ✓；另一个入口没认出项目也照样能用 ✓）|

### 两个设置（一般只需这两个）

```jsonc
// 项目的 .vscode/settings.json
{
  "pixelDiff.projectDir": "hardware/pixel",            // 放 fzz 的那层；相对路径相对工作区根解 ✓；留空 = 自动找
  "pixelDiff.fzzPattern": "^pixel-pcb-v\\d+.*\\.fzz$"  // 哪些文件算「一版」；默认 \\.fzz$（所有 fzz）
}
```

**`projectDir` 留空时的自动找法** ✓（顺序 ✓）：老路径 `<工作区>/hardware/pixel` ✓ ⇒
工作区根（自己含 fzz 就算 ✓）⇒ 往下**最多 3 层**找含 fzz 的目录 ✓
（扫的时候跳过 `.git` / `node_modules` / `__pycache__` / `.venv` / `tools` / `diff` / `build` /
`dist` / `out` / `target` ✓）。认出**多个** ⇒ 取 `diff/` **最近动过**的那个 ✓（正在干活的 ✓）；
再平就取路径短的 ✓。

**`fzzPattern` 为什么要给**：一个目录常混着好几套稿 ✓ —— 本项目实测 **151 个 fzz** ✓，
其中只有 **76 个**是 `pixel-pcb-v*` ✓，其余 75 个是面包板/原理图稿 ✓
⇒ 默认规则会把它们一起列进选择框 ✗ ⇒ 钉一下 ✓。

### 命令行兜底（不装扩展也能用 ✓）

```
python <库>\tools\diff_revs.py --dir <项目目录> --pattern ".*\.fzz$" v1 v2
python <库>\tools\diff_revs.py --dir <项目目录> --nets <项目>\<网表>.py a.fzz b.fzz
```

`--dir` 不给就用当前目录 ✓；`--pattern` 不给就是 `.*\.fzz$` ✓；`--nets` 不给就找
`<目录>/pixel_nets.py` ✓，**找不到也不报错** ✓（只是清单里少「网络」那一节 ✓）。
输出固定在 `<目录>/diff/diff-<A>-<B>.{svg,png,md}` ✓ —— 这个命名规则**与项目无关** ✓，
扩展与幻灯片认的就是它 ✓。

★ 扩展启动工具时传的是**绝对路径** ✓（`diff_revs.py` 的 `_resolve()` 直接命中 ✓）
⇒ **文件名怎么取都行** ✓（不再要求 `-vN` 那种名字 ✓）。
